    MT 07¶

    MINTERFASES Y APLICACIONES¶

    TECNOLOGÍA Y FABRICACIÓN

    Este Módulo Técnico 07 enmarcado en la fabricación digital nos introdujo en las Interfases y aplicaciones en el contexto de los microcontroladores electrónicos, para el IoT (Internet de las Cosas). Con el objetivo de comprender la utilidad y funcionamiento básica de una interfaz electrónica, como un sistema que facilita la comunicación (ver estados/variables) e interacción (ejecutar acciones) entre diferentes dispositivos electrónicos en la transmisión de señales de datos. Frente a un área ajena a mi formación (la ingeniería electrónica), me desafié un paso más, intentando profundizar en el tema, y a partir de lectura/literatura afín, (e infinidad de dudas liberadas a través de consultas y razonamiento conjunto con la IA), desarrollé este esquema sintético para comprender la configuración de la UI + UX en el ECOSISTEMA ELECTRÓNICO ~ ESP32:

    ❝ La interfaz no es un objeto sino un proceso, el lugar de la interacción. No es un simple adorno (…) que se añade al final para que el hardware sea más bonito; es el dispositivo de interacción que vincula a los actores humanos y tecnológicos ❞. [ Carlos A. Scolari . Universitat Pompeu Fabra . Barcelona ]

    ECOSISTEMA ELECTRÓNICO BASADO EN ESP32: Un ecosistema basado en ESP32 se compone de hardware (el chip ESP32, sensores, actuadores y PCB) y software (firmware, IDEs y protocolos). El hardware maneja la lógica física y conectividad RF, mientras el software gestiona la ejecución de tareas, Wi-Fi/Bluetooth y la interacción del usuario. En la interacción entre el Hardware y Software: El código creado en el IDE (Software) se compila y carga en la memoria del módulo ESP32 (Hardware). Este software utiliza las librerías para controlar en los microcontroladores los pines físicos GPIOs (Hardware), enviando datos a través de Wi-Fi a Webs Servers y plataforma-backend/frontend (como, Blynk IoT, Node-RED (Dashboards), etc).     DINÁMICA 1 . ESP32 ~ INTERFAZ USO ~ BLYNK . Arduino ESP32 Connectivity . sketch 1¶

    OBJETIVO La dinámica 1 se focalizó en montaje de una INTERFAZ DE USO (UI) a través de la ‘BLYNK‘(interfaz virtual de control y plataforma de software: APP + API + CLOUD), mediante la guía asistida de la AI Google Gemini Web (como co-creador del sistema circuital e instrucciones para la ‘movilidad energética’ y transferencia de datos electrónicos):

    Conectar la placa ESP32 a Blynk y controlar un LED incorporado con conexión a la red wifi > Prender y apagar un LED integrado en el módulo microcontrolador SP32.

    Resolverse mediante alguna la Interfaz a elección de las siguientes opciones, o una alternativa equivalente: + Interfaz física, ej. una pantalla junto con un encoder rotativo c/ pulsador integrado + Node-RED + Blynk + HTML + JavaScript servido desde el propio ESP32 + Cualquier otra interfaz que permita interactuar de forma clara con el sistema

    DINÁMICA 2 . ESP32 ~ INTERFAZ USO + ACTUADOR FÍSICO . Arduino ESP32 Connectivity . sketch 2¶

    OBJETIVO La propuesta debe permitir que el usuario pueda enviar acciones o cambios de estado al actuador desde la interfaz elegida. Además, se debe explicar brevemente: + qué actuador fue seleccionado, + qué interfaz se utilizó, + cómo se comunica la interfaz con el ESP32, + qué acción realiza el actuador al recibir la orden.

    La 2da dinámica consistió en: Generar un sistema de conectividad, ESP32 / Web Server / Sensor DATA DHT Display. Configurar el ESP32 como servidor web para monitorear variables ambientales (Humedad/Temp), un proceso que mezcla electrónica, redes y desarrollo web básico.

    PROMPT AI + PROCEDIMIENTO

    PASO 1 ~ SENSOR DHT22 CONNECT . (Hardware) 

    SENSOR DHT22 (temp/hum) → Esp32 : 
(DHT) pin 3 DAT → pin D4 GPIO-4 (esp32) + 
(DHT) pin 2 VCC → 3V3 (esp32) + 
(DHT) pin 1 GND → GND (esp32)

    PASO 2 ~ ARDUINO-IDE SETTING . (Software)

    P 2.1 ~ BOARD ESP32 INSTALL . (Arduino IDE)

    Según las indicaciones de conexión del circuito y características descritas sobre el Sensor DHT, mi Sensor DHT (con placa base PCB [*]), no necesita resistencia al estar integrada.

    [*] En el contexto de los sensores DHT (DHT11/DHT22), PCB se refiere a la Printed Circuit Board (Placa de Circuito Impreso) en la que viene montado el sensor. Esta PCB facilita su uso al integrar resistencias de pull-up (generalmente 5kΩ o 10kΩ) y pines soldados, convirtiendo el sensor de 4 pines a un módulo de 3 pines (VCC, GND, Datos) más seguro y sencillo para conectar a Arduino, ESP8266 o ESP32.

    PASO 4 ~ GRAPHICAL UI DISPLAY & Web Server - WiFi . (Software/Frontend + Backend)

    Activar Web Server WiFi (a través de la IP generada) para el sistema del circuito electrónico, vinculando sus componentes; Software-Backend [ Code arduino IDE + Red WiFi ] + Hardware [ ESP32 + DHT + PC ], para la visualización de la Interfaz Visual de Usuario (UI-Frontend).

    Para visualizar la interfaz gráfica de usuario (UI Visual/Canvas - Frontend), es decir el resultado visual de instrucciones (código/Script - Backend) que genera el microcontrolador ESP32, el dispositivo, “se convierte en un mini servidor” de internet (Web Server) privado dentro de “casa” a través del cual veremos la interfaz con el flujo de datos de temp. y hum. actualizados en tiempo real. Entonces, el ESP32 que actúa como un Webservidor que envía código (web) HTML al navegador, habilita el siguiente flujo de datos:

    1. LECTURA: El ESP32 lee los valores de dht. readTemperature() y dht. readHumidity().
    2. SERVIDOR: Crea una instancia (servicio) de WiFiServer = Server(80).
    3. INTERFAZ GRÁFICA de USUARIO (UI) <canvas> : El código debe generar un documento HTML que incluya los valores. Para que sea “gráfica” y se actualice sola, puedo usar: Meta Refresh: Para recargar la página automáticamente cada pocos segundos. CSS/Gráficos: Se puede incluir/incrustar estilos CSS directamente dentro del mismo archivo HTML utilizando las etiquetas <style> y </style>(ubicadas en la sección <head>), para crear tarjetas visuales o usar librerías como ThingSpeak (para crear una nube con gráficas avanzadas).

    PASO 5 ~ GRAPHICAL UI DISPLAY INTERACTION (Software/Frontend)

    Ahora que la lógica “backend” (la comunicación de red y la lectura del sensor) funciona a la perfección, podemos enfocarnos 100% en el “frontend” (la interfaz que ve e interactúa el usuario). Explorando distintas versiones de Código y sus variables de instrucciones (script/Backend)para enriquecer el Canvas Visual (UI “Frontend”), identifiqué dos versiones de INTERFAZ GRÁFICA DE USO posibles: 1.INTERFAZ GRÁFICA (HTML + CSS + JS NATIVO Y OFFLINE) y 2.INTERFAZ GRÁFICA (HTML + CSS + JS CON HIGHCHARTS).

    1. // — INTERFAZ GRÁFICA (HTML + CSS + JS NATIVO Y OFFLINE) —–

    UI VERSIÓN NATIVA/OFFLINE: En este caso, modifiqué (por partes) algunas variables que necesitaba para enriquecer el código e ir entendiendo cómo se comunican las distintas partes del programa de código de instrucciones (el “Front-end” o diseño, y el “Back-end” o cerebro) y así obtuve distintas variantes de UI enriquecidas:

    A . UI enriquecida básica (offline): Apliqué un cambio visual de estilo tipo “Dark Mode” con cajas de sombras, diseño adaptable (responsive) a otros formatos de dispositivos (ej. Mobile).

    CÓDIGO NUEVO ~ INTERFAZ Web A

    B. UI enriquecida interactiva (offline): En este caso para hacer la interfaz más interactiva, añadí gráficas en tiempo real que dibujaran el historial reciente de temperatura y humedad, aplicando un cambio visual de estilo tipo “Dark Mode”. Este resultado de interfaz interactiva es una fusión entre ambas versiones básicas combinando entre sí distintos componentes variables de interés de ambos códigos.

    CONEXIÓN ~ Hardware + WebServer para última versión de interfaz enriquecida.

    CÓDIGO NUEVO ~ INTERFAZ Web B

    Componentes del código redefinidos para UI (interfaz B):

    UI_1 ~ Code Canvas: Agregué Gráficas ilustrativas que expresen de forma dinámica el flujo de datos variable Temp/Hum. La inclusión y funcionamiento de los gráficos se divide exactamente en tres bloques clave.

    UI_2 ~ Code Botón interactivo: Agregué botón interactivo (Tarjeta control LED) + la función clic que envía la orden al ESP32 al hacer clic en botón on/off luz led azul integrado en la ESP32. Agregar el “Cerebro” del botón al ESP32 > LED PIN Sensor: definición + configuración + ruta web recepción clic LED on/off.

    UI_3 ~ Code Iteración flujo de datos Hum/Temp: Cambié la solicitud de flujo de datos, variando la velocidad de consultas de flujo de datos de TEMP y HUM de 2000 a 2500, para que las gráficas visualicen con agilidad el flujo de datos variable.

    2.// — INTERFAZ GRÁFICA (HTML + CSS + JS CON HIGHCHARTS) —

    UI VERSIÓN HIGHCHARTS: En este caso para hacer la interfaz más avanzada, para las gráficas se podría usar una librería Highcharts, gratuita profesional externa al ESP32 (el código no está guardado dentro de la memoria del ES32). En la versión Highcharts la librería es muy potente y ofrece un paquete de código inmenso, pesado y muy avanzado creado por otra empresa. Cómo es demasiado grande para guardarlo cómodamente dentro de la pequeña memoria del ESP32, ese código “vive” en servidores en Internet. + info [ Librería JavaScript HIGHCHARTS ]
