Este **_Módulo Técnico 07_** enmarcado en la fabricación digital nos introdujo en las **_Interfases y aplicaciones en el contexto de los microcontroladores electrónicos_**, para el IoT (Internet de las Cosas). Con el objetivo de comprender la utilidad y funcionamiento básica de una **interfaz electrónica**, como un sistema que facilita la **comunicación (ver estados/variables) e interacción (ejecutar acciones) entre diferentes dispositivos electrónicos en la transmisión de señales de datos**. Frente a un área ajena a mi formación (la ingeniería electrónica), me desafié un paso más, intentando profundizar en el tema, y a partir de lectura/literatura afín, (e infinidad de dudas liberadas a través de consultas y razonamiento conjunto con la IA), desarrollé este esquema sintético para comprender la configuración de la UI + UX en el ECOSISTEMA ELECTRÓNICO ~ ESP32: 
<br>

_❝ La interfaz no es un objeto sino un proceso, el lugar de la interacción. No es un simple adorno (...) que se añade al final para que el hardware sea más bonito; es el dispositivo de interacción que vincula a los actores humanos y tecnológicos ❞._ _[ Carlos A. Scolari . Universitat Pompeu Fabra . Barcelona ]_
<br>

![](../images/MT07/MT07_ecosistem_ESP32.png)

**ECOSISTEMA ELECTRÓNICO BASADO EN ESP32**:  Un ecosistema basado en ESP32 se compone de hardware (el chip ESP32, sensores, actuadores y PCB) y software (firmware, IDEs y protocolos). El hardware maneja la lógica física y conectividad RF, mientras el software gestiona la ejecución de tareas, Wi-Fi/Bluetooth y la interacción del usuario. En la **interacción entre el Hardware y Software**: El código creado en el IDE (Software) se compila y carga en la memoria del módulo ESP32 (Hardware). Este software utiliza las librerías para controlar en los microcontroladores los pines físicos GPIOs (Hardware), enviando datos a través de Wi-Fi a Webs Servers y plataforma-backend/frontend (como, Blynk IoT, Node-RED (Dashboards), etc). _[ VER LINKS DE INTERÉS ~ pie pág.]_

**PASO 4** ~ GRAPHICAL UI DISPLAY & Web Server - WiFi . (Software/Frontend + Backend)

Activar Web Server WiFi (a través de la IP generada) para el sistema del circuito electrónico, vinculando sus componentes; Software-Backend [ Code arduino IDE + Red WiFi ] + Hardware [ ESP32 + DHT + PC ], para la visualización de la Interfaz Visual de Usuario (UI-Frontend).


Para visualizar la **interfaz gráfica** de usuario **(UI Visual/Canvas - Frontend)**, es decir el resultado visual de instrucciones (código/Script - Backend) que genera el microcontrolador ESP32, el dispositivo, "se convierte en un mini servidor" de internet (Web Server) privado dentro de "casa” a través del cual veremos la interfaz con el flujo de datos de temp. y hum. actualizados en tiempo real. Entonces, el ESP32 que actúa como un Webservidor que envía código (web) HTML al navegador, habilita el siguiente flujo de datos:

![](../images/MT07/MT07_ej2_Gem_paso4.png)

1. LECTURA: El ESP32 lee los valores de ```dht. readTemperature() y dht. readHumidity().```
2. SERVIDOR: Crea una instancia (servicio) de WiFiServer = Server(80).
3. INTERFAZ GRÁFICA de USUARIO (UI) ```<canvas>``` : El código debe generar un documento HTML que incluya los valores. Para que sea "gráfica" y se actualice sola, puedo usar:
**Meta Refresh**: Para recargar la página automáticamente cada pocos segundos.
**CSS/Gráficos**: Se puede incluir/incrustar _estilos CSS_ directamente dentro del mismo archivo HTML utilizando las etiquetas ```<style> y </style>```(ubicadas en la sección ```<head>```), para crear tarjetas visuales o usar librerías como ThingSpeak (para crear una nube con gráficas avanzadas).
